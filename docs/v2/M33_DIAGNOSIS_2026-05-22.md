# m33 진단 — 2026-05-22 (false positive + cron UX 개선)

## 1. 가설 vs 사실

### 1.1 원래 가설 (직전 세션)
- `weekly_quality_report` 적재 누락 (5/11·5/18 주)
- `generate_weekly_quality_report` 함수 silent fail 의심

### 1.2 사실 — false positive
| 검증 | 결과 |
|---|---|
| 함수 본체 분석 | 정상 (`v_upserted` 카운트 + ON CONFLICT UPDATE) |
| upstream `prediction_quality_daily` | 5/11~5/21 매일 6~13건 정상 |
| 5/11 주 수동 실행 | **10 rows 정상 적재** |
| 기존 cron jobid 9 동작 | 정상 (silent fail 아님) |

### 1.3 사용자가 누락이라 인식한 이유 — cron 설계상 UX 불편
cron command:
```sql
SELECT generate_weekly_quality_report(
  (date_trunc('week', CURRENT_DATE) - INTERVAL '7 days')::date,
  'v6.2')
```

| cron 실행일 | 생성되는 주 |
|---|---|
| 5/17 일요일 | 5/04 주 (정상 적재됨) |
| **5/24 일요일** | **5/11 주** (오늘 5/22 시점에는 아직 미생성이라 누락처럼 보임) |
| 5/31 일요일 | 5/18 주 (아직 진행 중인 주) |

→ 일요일마다 **이전 한 주만 생성**. 따라서 5/22(금) 시점에 5/11 주가 비어있는 것은 **정상 동작**이었으나 사용자에게는 "누락"으로 보임.

## 2. 적용된 fix (UX 개선)

### 2.1 helper 함수 신설
`refresh_weekly_quality_recent(p_weeks int DEFAULT 4, p_model_version text DEFAULT 'v6.2')` — 최근 N주를 일괄 backfill (`ON CONFLICT UPDATE` 멱등).

마이그레이션: `m33_refresh_weekly_quality_recent`

### 2.2 cron jobid 9 → 15 갱신
- 기존: `generate_weekly_quality_report(...1주...)` 단일 호출
- 변경: `refresh_weekly_quality_recent(4, 'v6.2')` — 매주 일요일 20:00 UTC에 최근 4주 일괄 처리
- 효과: 일요일 cron이 1회 실행 시 i=1..4 루프로 4주 모두 갱신 → "다음 주 까지 안 보이는" UX 불편 제거

마이그레이션: `m33_cron_weekly_report_4w_backfill` (unschedule jobid 9 + 새 jobid 15 등록)
