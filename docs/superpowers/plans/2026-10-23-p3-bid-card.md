# P3 투찰 카드 + 예측 기록 탭 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 상세 모달(하위 탭 5개, 숫자 30개 이상)을 3블록 "투찰 카드"로 교체해 오늘의 공고와 예측 기록 어디서든 열리게 하고, 예측 탭을 "예측 기록"으로 줄이며, 그로 인해 죽는 상태·조회·옛 엔진 화면 코드를 삭제한다.

**Architecture:** 행 단위 추천 계산을 순수 함수 `recOfPred(p, deps)`(의존성 주입, 테스트로 출처 격리 고정)로 뽑아 오늘의 공고 표와 카드가 같은 값을 쓰게 한다. 발주처 1위 이력은 메모리의 `recs`에서 순수 함수로 계산해 느린 서버 RPC(`get_agency_hist_stats_batch`)를 없앤다. 카드는 새 컴포넌트 `BidCard.jsx`(앱 다크 팔레트)로 만들고 App.jsx 최상위에서 렌더한다. 나머지는 삭제다.

**Tech Stack:** React 18 + Vite, `node --test tests/*.test.mjs`(eq 헬퍼 + exit code), 팔레트 `C`(`src/lib/constants.js`).

**Spec:** `docs/superpowers/specs/2026-10-22-bid-ops-funnel-redesign-design.md` §6.3(투찰 카드)·§6.5(제거)·§10. predict-architect 판정(2026-10-23): **Neutral**(표시층), `/evaluate` 면제 — 아래 유지 조건을 지킬 때만.

**사용자 결정(2026-10-23):** 예측 탭은 "예측 기록"으로 축소 / 수동 시뮬레이션 삭제 / AI 분석 탭 삭제 / 1월 15일 건은 동가 추첨이라 적격 체크리스트 없음 / 군부대(Mode A) 카드 메인 숫자도 하한 통과 확률 / 예측 삭제 기능은 만들지 않음.

## Global Constraints

- **diff 0줄 (Neutral 유지 조건)**: `getFinalRecommendation` 본문(격리 주석 포함), App.jsx의 `bid1st_v2`·`b_pred` 백필 effect 2개, `loadPredFiles`의 저장 행 조립(`dbRows`), `utils.js`(predictV5·recommendMain·recommendBid1st·recommendV2·recommendAssumedAdj), `eraFR`/`calcEffectiveFloorRate`, `supabase.js`의 쓰기 함수.
- `getFinalRecommendation`은 **`source==='file_upload'` 행에만** 호출한다. 자동 예측은 저장된 `b_pred_*`(mode 'B')만 읽는다. 이 규칙은 Task 1 테스트로 고정한다.
- 유지 필수(지우면 안 됨): `agencyPred`(predictV5 입력), `sbRecordSnapshots` 호출 2곳(필터만 `scoringMap` → 전체 예측으로), `sbMatchPredictions`, `sbUpdateStrategyOutcomes`, 새로고침 버튼(`refreshAll`), 예측 파일 드롭존, `md2html`(AI 상담 탭), `getBiasArrow`·`predConfidenceV2`(리스트), 탭 id `"predict"`(focusedPredId·자동 새로고침 effect가 의존 — 라벨만 바꿈).
- 카드 표시: 사정률 `(100+adj).toFixed(4)+"%"`(오늘의 공고 표와 같은 4자리), 통과 확률은 `floorPassLabel(100-passPct)`(">99%" 규칙), 투찰금 원 단위. "낙찰 확률" 문구 금지(모든 모드). "확정/제출" 버튼 금지. 이모지 없음.
- 공유 배열(`recs`, `predictions`) 제자리 변형 금지(`[...arr].sort`만).
- 빌드가 지운 식별자 참조를 잡지 못한다(린터 없음 → 런타임 흰 화면). 삭제한 식별자마다 `grep -c`=0 확인이 완료 조건이다.
- 완료 전 `npx vite build` + `node --test tests/*.test.mjs` 통과, 브라우저에서 대시보드·오늘의 공고·예측 기록 세 탭 렌더 + 카드 열기 확인. push는 사용자 승인 + deploy-gate.

## Review Focus

1. 자동 예측(g2b_auto) 행이 어떤 경로로도 `getFinalRecommendation`에 들어가지 않아야 한다(보정 2겹) → Task 1 스파이 테스트.

### Task 1: 순수 함수 — 행 추천 계산·발주처 1위 이력 (`bidCard.js`)

**Files:**

**Interfaces:**
- Produces:
  - `export function recOfPred(p, deps): { adj, bid, passPct, jongsim, estimated, floorSafe, source, mode, distN, distGrain } | null`
    - `deps = { getFinal(p), adjHist, passKeyOf(p), passEffFrOf(p, ownScore), ownScore, resolveAdjHistory(hist, key), passProbPct(dist, implied), impliedAdjOfBid({bid,ba,av,effFr}) }`
    - `p` 없으면 null. `match_status` 무관(matched도 계산).
    - `source==='file_upload'`: `r=deps.getFinal(p)` → `adj=r.adj`, `bid=r.bid1st||r.bid`, `jongsim=!!r.jongsim`, `floorSafe=r.floorSafe??null`, `estimated=false`.
    - 그 외: `p.b_pred_mode==='B' && b_pred_adj!=null && b_pred_bid_amount!=null`이면 `adj=Number(b_pred_adj)`, `bid=Number(b_pred_bid_amount)`, `estimated=true`; 아니면 adj·bid null. **getFinal 호출 금지.**
    - `passPct`: `!jongsim && bid && p.ba`이고 `dist=resolveAdjHistory(adjHist, passKeyOf(p))`가 있으면 `passProbPct(dist, impliedAdjOfBid({bid:Number(bid), ba:Number(p.ba), av:Number(p.av)||0, effFr:passEffFrOf(p, ownScore)}))`. `distN = dist?.length ?? null`, `distGrain = dist?.grain ?? null`(없으면 null).
    - `mode = p.b_pred_mode || (p.at==='군시설' ? 'A' : 'B')`.
  - `export function agencyRecentHistory(recs, canonicalAg, n = 20): { rows: {od, br1, ar1, pn}[], p25, p50, p75, count }`
    - `recs` 중 `(r.canonical_ag||r.ag)===canonicalAg` && `br1` 수치 && `od` 있는 행, `is_excluded!==true`. 개찰일 내림차순 상위 n. 분위수는 그 n건의 `br1`(100 기준 %) 기준, 소수 4자리. 없으면 `{rows:[], p25:null, p50:null, p75:null, count:0}`. 원본 불변.
